# Eisenhower Task Management

## Idea

A task management application built around the **Eisenhower Matrix**.

The idea is to combine a simple to-do list with a visual four-quadrant layout, allowing the user to organize their tasks according to their own judgment of importance and urgency.

## Basic Flow

The user first writes down the tasks they want to do in a general task list.

After creating the tasks, the user places each task into whichever Eisenhower Matrix quadrant they believe it belongs to.

The application therefore acts as a space for the user to **write, organize, and manage tasks**, while the prioritization decision remains with the user.

## Eisenhower Matrix

The main task area is divided into four sections using two intersecting lines.

Each section represents one quadrant:

- **Important + Urgent**
- **Important + Not Urgent**
- **Not Important + Urgent**
- **Not Important + Not Urgent**

Tasks are placed inside their respective quadrant.

## Visual Direction

The interface could have a **handwritten / hand-drawn visual feel**.

The exact extent of this style is still open. It may apply to the overall UI or only to certain elements, depending on how the concept develops.

The matrix itself should feel like a visual workspace rather than a conventional rigid task-management interface.

## Completing Tasks

When a task is marked as complete, it should **remain in the quadrant where it was placed**.

Instead of disappearing or being removed from the list, the completed task should be visually marked by having a **scribbled / hand-drawn strike-through** over it.

This keeps the completed task visible while clearly distinguishing it from unfinished tasks.

## Open Direction

The idea is intentionally open at this stage.

The core concept is the combination of:

**Task List → User Prioritization → Eisenhower Matrix → Persistent Completed Tasks**

The exact UI, interaction details, and visual treatment can be explored later.
